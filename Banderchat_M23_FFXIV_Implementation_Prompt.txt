==================================================
GOAL
==================================================

Implement Final Fantasy XIV as Banderchat’s next first-class World package using the M12–M22 architecture.

This is NOT a request to build an FFXIV encyclopedia.

MiMo already has substantial FFXIV knowledge.
The purpose of Banderchat’s FFXIV package is to provide:
- timeline guardrails
- zone / arc anchoring
- spoiler-state grounding
- optional-content continuity
- deterministic RPG mechanics
- FFXIV-specific theme
- FF Free Mode crossover support

==================================================
DO NOT DO THESE THINGS
==================================================

DO NOT:
- hardcode giant lore summaries into every prompt
- send the entire FFXIV timeline every turn
- rebuild the generic World / Scenario / Run architecture
- replace deterministic state validation with AI judgment
- recreate FFXIV MMO rotations one-to-one
- fabricate HP / MP / levels / gauges when not configured
- normalize all characters to equal power
- merge Scene Cast and Active Party
- make all Scions automatically active party members
- invent new canonical FFXIV facts to fill gaps
- begin giant portrait-generation or asset-generation work
- make FF Free Mode require full canon databases for every Final Fantasy game

1. FIRST-CLASS WORLD
==================================================

Create/selectable World:
Final Fantasy XIV

world-ffxiv

Integrate with existing:

==================================================
2. THIN TIMELINE ENGINE
==================================================

Implement data-driven FFXIV timeline checkpoint definitions based on the attached Thin Timeline Guardrails document.

Required hierarchy:
Expansion
→ Patch / patch range
→ Arc / zone phase
→ Current location

A Run must be able to store:
- expansion
- patch
- arcId
- locationId
- completed milestones
- locked future knowledge
- optional story states

The current arc packet sent to the RP model should be concise.

Example target context:

Expansion: Endwalker
Patch: 6.0
Arc: Garlemald
Location: Garlemald
Already happened: Sharlayan arrival; first Thavnair visit; Ilsabard contingent formed
Current: imperial capital collapsed; survivors distrust outsiders; Tower of Babil active
Not yet: Zodiark defeated; Meteion known; Elpis visited; Ultima Thule

Do not send irrelevant timeline entries.

==================================================
3. TIMELINE START SELECTOR
==================================================

Scenario / Run setup should allow the user to choose a starting timeline checkpoint.

Target UX:
Expansion selector
→ Patch / range selector
→ Arc selector
→ optional location override when appropriate

This may be a reusable timeline-picker component, not FFXIV renderer spaghetti.

==================================================
4. LIVE PROGRESSION
==================================================

The model may PROPOSE a timeline advance.
The deterministic engine validates it.

Do not let the model arbitrarily jump arcs.

Timeline transitions should use explicit milestone conditions.

Manual timeline advancement / timeskip must also be supported.

==================================================
5. OPTIONAL CONTENT / RAID STATE
==================================================

Implement the attached optional-content framework.

NOT_STARTED
IN_PROGRESS

COMPLETED_OFFSCREEN

Include at least:

- Crystal Tower

Optional completion must affect model grounding where relevant.

==================================================
6. SPOILER / KNOWLEDGE GATING
==================================================

Each timeline arc may define future facts that should not yet be treated as known.

Examples:
- pre-Amaurot Shadowbringers should not expose full Ancient revelations
- pre-Elpis Endwalker should not expose full Final Days cause
- early Dawntrail should not casually expose Alexandria / Solution Nine late-story revelations

This is a guardrail, not a giant lore database.

- survivors

Tuliyollal early 7.0:
- rite of succession
- Tural politics

The generated RP context should prioritize local relevance and suppress random unrelated old-zone chatter.

8. FFXIV RPG SYSTEM
==================================================

Implement an FFXIV RPG configuration using existing generic deterministic game-state / encounter systems.

Do NOT recreate MMO combat exactly.

Implement data structures for:
- FFXIV stats
- HP / MP where configured
- job identity
- compact ability kits
- optional simplified job gauges
- statuses
- Limit Break
- boss telegraphs / turn objectives

Seed representative job definitions for at least:
- Dragoon
- White Mage
- Black Mage
- Warrior
- Summoner
- Reaper
- Blue Mage

Use the attached combat framework as authority for the intended abstraction.

10. CANON POWER
==================================================

Do not secretly flatten canon characters to equal power.

Strong characters may be strong.
Challenge may come from objectives, protection duties, comparable enemies, time pressure, or consequences instead of fake normalization.

11. ACTIVE PARTY VS SCENE CAST
==================================================

Preserve existing architecture.

Do not automatically place every Scion or NPC in the combat party.

13. FF FREE MODE
==================================================

Implement FF Free Mode as a separate FFXIV-derived scenario/run mode.

Premise:
R'kuruh uses Ethos to travel into another Final Fantasy world.

Persist configured:
- R'kuruh continuity
- chosen companions
- memories / relationships
- limited gear / inventory

Destination world package may be lightweight.
It should preserve broad destination:
- character identities
- factions
- iconic locations
- magic / technology rules

Exact story chronology can be relaxed unless user pins a specific checkpoint.

The local protagonist still exists.
R'kuruh does not automatically replace them.
